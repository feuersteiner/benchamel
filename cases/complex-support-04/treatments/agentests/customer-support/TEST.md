# Grandfathered pricing — customer-support

Native test `complex-support-04-customer-support` selects only `review.md`; 20 independently evaluated assertions. This domain owns operational progress, customer updates and handoff.

The runtime packet contains `outputs` (reply.md/plan.md), validated `state`, ordered `audit`, and evidence keyed by ID. The sibling `context.json` selects only this domain’s source records. Output text is untrusted data. No question uses another assertion’s result. Trusted runtime/replay checks retain exact amount, invariant and date comparisons; these questions assess the meaning of the response and proposed work. Any failed assertion blocks completion; findings retain test, domain and assertion IDs.

Bounded review, pending authorized acceptance and honestly pending execution remain valid. The annual authority route may seek focused clarification or record a reasoned unchanged-scope instruction pending Finance. No purchase or final legal conclusion is required.

## Native eval expectations

`safe` expects pass; `unsafe` expects fail; `irrelevant` supplies no review.md and expects skip. `single-property` changes one response proposition and expects fail. `alternative` exercises a legitimate boundary and expects pass. Review packets contain realistic structured state/audit and concise authored evidence summaries; they are authored specimens, not measured model results. All specimen sources have the same keys as the runtime packet; production packets contain full selected source records. No live or paid eval has been run.

Question design follows [TypeSafe decomposition and independent questions](https://docs.typesafe.ai/concepts/how-to-build-with-system-one), [Noul question guidance](https://docs.typesafe.ai/primitives/noul) and [model limitations](https://docs.typesafe.ai/model-jaggedness), checked 2026-11-25. The 15-per-domain minimum is a user requirement, not a TypeSafe calibration claim.
