# E15 — Integration access, evidence minimization and preservation

Record version: SEC-IMP-3.4. Owner: RelayGrid Security Operations. Effective: 2025-04-15. Case note: 2025-06-12 11:30 UTC. Status: current access policy and verified project permissions.

The project uses synthetic staging orders with invented company and item codes. The production tenant contains company account settings and integration configuration but has not been approved for general commercial processing. Warehouse service credentials are held by Vela's nominated custodian. Owen can request rotation and a narrowly scoped service account. Staff must not copy secrets into support tickets, test reports or partner correspondence. A vendor engineer's ability to view configuration does not create permission to use a customer's warehouse account for a new commercial purpose.

Northstar currently has staging transformation access, not unrestricted production administration. Its report request can be satisfied with source references, sanitized payload fields, mapping versions and downstream commit states. Broad production access would require Vela authorization, security review and an expiry. No current approval permits giving the partner a shared administrator account to save time. Signature and access checks must remain enabled in any new event path. Turning them off to obtain a green response can create false test evidence and expose unauthorized actions without solving the retry defect.

June 11 staging evidence is retained in project store P-218. Jules recorded a preservation receipt at June 12 10:30 covering T-40, T-41, connector version and mapping hashes. Retention runs through July 12. Northstar's warehouse emulator resets nightly at 22:00 UTC, so each new run needs a downstream export before reset. Preserved payloads do not contain real customer addresses, contact details or payment data. If commercial pilot data is later introduced, the same evidence objective must use minimized identifiers and appropriate restricted storage, not public attachments.

A complete implementation review does not require raw unrelated tenant logs or full accounting data. Customer-facing reports may show aggregate results and Vela-specific synthetic references with explanation of limits. Partner-specific pricing and contract negotiations may be summarized only as necessary for scheduling and customer choice. Internal commercial strategy should not be pasted into an external status report. Conversely, confidentiality is no basis to conceal the existence of a reproduced vendor defect or the fact that a critical test remains unpassed.

Credential rotation is booked with Vela for June 13 at 08:30 UTC. It can be completed before a later approved production pilot if the custodian attends; it has not occurred yet. Staging diagnosis today requires no production secret. If a pilot approval arrives but rotation fails, the route remains inactive and the owner reports the failed prerequisite. The security team can advise on access boundaries but cannot accept the operational pilot, change the SOW or approve financial relief. A security checklist completed in isolation therefore cannot establish end-to-end readiness or supersede the customer consent requirements in E03 and E07.
