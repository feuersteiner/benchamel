# E08 — RelayGrid connector findings and limits

Record version: ENG-218.6. Owner: engineer Jules Tran. Dated: 2025-06-12 10:45 UTC. Status: preliminary reproducible findings from staging T-41; no commercial order replay authorized.

T-41 contained 240 synthetic order events covering 120 distinct orders. Testers intentionally repeated each initial event once after simulated acknowledgment loss. Every request reached RelayGrid's gateway, and 240 transport acknowledgments were returned. The warehouse emulator recorded 123 reservations: 117 orders had one reservation and three orders had two. No invoice was produced because the accounting adapter was disabled for this run. Successful transport delivery therefore coexists with three duplicate business effects; an all-green gateway dashboard alone is not an operational success measure.

The duplicates occur on the path where the warehouse commits a reservation but the connector loses the response. Retry key handling uses a local attempt identifier on that branch instead of the durable source order reference. RelayGrid owns this branch under Appendix B. Jules reproduced the defect with the unchanged baseline mapping. This supports a vendor defect independent of Vela's late classification file. It does not establish that all failures in earlier batches had the same cause or that Northstar's transformation never contributes to other problems. An engineer can accept responsibility for a boundary without deciding every commercial claim.

Patch C-19 changes the retry key and adds an audit record. It passed the narrow duplicate test at 09:50 with 120 distinct orders and 120 reservations. The patch is in staging only. It has not passed the warehouse outage, partial shipment, accounting reconciliation or representative-volume tests. Jules estimates one engineer-day to complete targeted tests if the warehouse sandbox remains available, with broader testing possibly longer. This is an effort estimate, not a promise of production readiness by June 16. A release candidate would still need change approval and customer operational sign-off.

There is a separate stale-status issue. When the warehouse rejects a mapped item, RelayGrid displays received until the rejection polling task runs. The task currently runs every fifteen minutes in staging. A user may read received as reserved, though the UI legend distinguishes them. Engineering can change the label and improve alerting, but neither change validates an incorrect mapping. Test operators need the source reference and downstream commit report for reconciliation. The dashboard retains failed attempts; it must not be filtered to make the launch record appear cleaner.

Production impact is limited by the current route: the legacy feed remains primary and the new connector has not been authorized to transmit live orders. Two duplicate reservations discussed by Owen belong to staging batch T-40, not known commercial shipments. Production tenant credentials exist but no evidence establishes a general live switch. Engineering has no record that Vela inventory or funds have been lost. Preservation of staging logs and versions through July 12 is requested because ownership remains disputed. Log retention does not itself authorize sharing credentials, personal customer data or unrelated tenant records with the partner.
