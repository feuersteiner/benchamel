# E06 — Superseded implementation playbook and inherited ticket

Record version: DEL-3.1. Owner: Delivery Operations archive. Effective: 2024-09-01 through 2025-04-30. Retrieved into project ticket: 2025-05-06. Status: superseded; retained to explain a live workflow reference.

The old playbook allowed a project coordinator to move an implementation from configuration to launched when the production tenant was provisioned, the main connector returned successful transport responses and a nominated customer user attended a demonstration. The launched field generated a recommended milestone invoice task. A separate finance check was still required before actual billing. The document did not provide a general right to collect fees contrary to an executed order. The simplified checklist was designed for single-service deployments, before joined warehouse and invoicing implementations became common.

Under this version, unresolved partner issues could be transferred to a separate support queue once the vendor endpoint was reachable. The procedure required an owner and case link, but it did not require a shared end-to-end acceptance register. Several projects consequently used launched to mean different things. An April internal audit found that transport green status was being read as operational acceptance in some account reports. The audit is the stated reason DEL-4.3 replaced this procedure. No individual Vela transaction was reviewed in that general audit.

Vela ticket IMP-218 was created February 3 from this template. Its closure checklist still contains a link to DEL-3.1 and a field named customer endpoint complete. On May 6 a coordinator copied the template link while moving the project between queues. The history contains no note saying the old policy was specially extended for Vela. The production tenant was provisioned May 28; a demonstration occurred May 30 with synthetic happy-path orders. Those facts explain the green configuration tile, but do not establish the signed SOW acceptance or the current policy's launch evidence.

Alec's June 10 account forecast cites the tile as a signal that the implementation will count as delivered this quarter. Finance's acceptance gate is independent of that forecast. The old template also contains a placeholder for a premium support quote, which did not create a customer order. Neither the template nor Alec's forecast records Sera's agreement to purchase more service. A commercial report can explain staff pressure without supplying technical readiness or customer consent.

The archive custodian marked the link stale on June 11 at 18:00 and notified project owners. The old text remains visible for audit and cannot be edited to make the project history look cleaner. Delivery Assurance asks that any current decision cite DEL-4.3 and the signed SOW, while retaining the old status mapping in the record. The stale workflow is a plausible source of confusion rather than evidence that every statement made under it was knowingly deceptive. Responsibility for the present response depends on the current evidence available at the cutoff, including the correction notice, not solely on which template originally opened the project.
