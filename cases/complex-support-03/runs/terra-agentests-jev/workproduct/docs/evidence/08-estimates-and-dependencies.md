# E08 — Recovery estimates with incompatible scopes

Record version: EST-619.2. Owner: incident program manager Tavi Ross. Consolidated: 2025-05-14 11:10 UTC. Status: working estimates, not committed completion times; all times UTC.

At 08:20 database engineer Jules estimated six hours to restore N-011 after allocation of a database host. That estimate covered transfer, decompression, database start and basic table checks. The host became available at 09:00, so a literal six-hour projection would end at 15:00. It did not include attachment relationships, replay of the 74 accepted changes, application identity checks, customer validation or production release. A sales note later rendered this as all data back by 15:00. Jules has not endorsed that broader wording.

At 10:30 application engineer Noor Ives estimated that a fully reconciled production workspace would most likely be ready between 18:00 today and 06:00 tomorrow if N-011 can be used and the missing chain segment is retrieved. If the segment is unavailable, the team must characterize missing approvals and seek customer decisions; no reliable latest-state completion time is available. Noor's range includes application and relationship validation, not tender portal processing or Meridian's own engineering review. The range is an estimate conditional on successful checks, not a service commitment or evidence of likely full recovery.

At 10:55 the export specialist estimated a read-only baseline extract could be assessed for release by 14:30 if assigned by 12:15. That deliverable would be N-011 metadata with only attachments whose relationships pass validation, a known-gap register, original identifiers and a conspicuous 01:00 recovery-point label. It would not include the 06:45 approvals unless separately reconciled. The specialist has reserved capacity pending an instruction. A checkpoint at 13:15 can report whether the artifact remains feasible; it cannot guarantee the file or certify tender acceptance.

Manual reconstruction has a different dependency. Owen can compare local exports and email evidence in parallel, but he needs the existing signed approval roster and a discrepancy list. He estimates two to four hours for a minimum offline pack if engineers are available before 12:30. That is Meridian's staffing estimate, not a Flint Ledger commitment. The portal's 16:30 upload planning time leaves little room for discovering further gaps. Requiring the customer to wait until 18:00 before starting would remove that option without proving that full recovery will succeed.

Tavi directs update owners to describe the object of each estimate and its start condition. Staffing constraints mean the export worker and an extended application reconciliation sprint cannot both use Noor continuously from 12:15 to 14:30. Isolated baseline export work can proceed with the specialist and time-boxed Noor review, delaying full application reconciliation by an estimated 45–75 minutes. Alternatively, focused full-chain investigation keeps that capacity but leaves the customer dependent on its own files for today's pack. No source establishes that either schedule will meet the external tender deadline.
