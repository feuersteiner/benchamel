# E06 — Archived launch checklist and incomplete green status

Record version: REL-4.2/ARCHIVE-19. Owner: delivery operations. Effective 2026-06-01 through 2026-10-31; archived November 1. Historical review compiled 2026-11-23 12:15 UTC. This is historical process evidence, not current approval.

The old checklist let the implementation manager mark an account ready after a content review, smoke test and automated accessibility scan of five representative pages. It required an exception ticket for serious manual findings but did not clearly distinguish static information pages from the complete application flow. A team could obtain a green dashboard with a functioning login and an untested upload dialog. The dashboard's short label was intended for internal scheduling. Some sales staff later pasted it into customer decks as launch readiness, although the checklist did not grant authority to make conformance or certification statements.

Rivermere's October 22 run used this procedure. The five scanned routes were the home page, funding criteria, contact page, login and an empty eligibility page. The new evidence widget did not appear in the scanned state because the test account had no eligible draft. The file record says zero severe automated findings on those routes. It does not say zero accessibility barriers, complete manual testing or acceptance by Ruth. The scan operator did not use a screen reader. The report's export footer omitted those scope limitations, making the later screenshot especially easy to overread.

An October 24 project note from former implementation manager Noel Pike says green means the website is safe for the campaign team to prepare notices. The same note asks for a manual application walkthrough before opening intake. Noel left the project on November 5. A calendar invitation still names him as launch approver, but the November authority table supersedes that delegation. His old note cannot authorize a launch after a new critical finding. The inaccurate calendar entry has not yet been corrected in the coordination system; it helps explain a routing delay, rather than proving that no current owner exists.

An October 29 release rehearsal also has a green badge. It concerns build 8.3 without the November 12 upload change. The developer successfully submitted a sample using a mouse. There is no keyboard-only error-path recording, screen-reader result or rejected-upload retest. A separate table showing high contrast for the campaign logo is accurate within its scope and irrelevant to whether the declaration can be reached. Both records should remain available instead of being silently edited to appear more comprehensive. Their limited scope matters to the correction of the sales attachment.

The current policy requires a new blocked status when a critical barrier is reproduced. Delivery has preserved the old dashboard for audit but has permission to append a visible current-state note. A proposed dashboard automation would expire readiness badges after a module change; it is not deployed. Staff must use the actual authority and current evidence at the cutoff, not a planned automation. There is no factual basis to blame Ruth for failing to understand that a green internal badge concealed an untested step when the customer-facing export never described that limitation.
