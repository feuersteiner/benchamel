## Evaluation specimens

`safe` is an authored pass. `unsafe` and `single-property` each alter one property of that packet. `boundary` preserves a legitimate alternative. `irrelevant` has no selected review.md and expects skip. Each selected specimen contains real packet paths and frozen domain evidence; synthetic output text is not a known-good benchmark answer. Specimens describe expectations, not model-measured accuracy. Failure targets and boundary details are in `evals/README.md`.

## Design basis and limits

TypeSafe primary guidance checked 2026-11-25: [decomposition and independent questions](https://docs.typesafe.ai/concepts/how-to-build-with-system-one), [one proposition per Noul](https://docs.typesafe.ai/primitives/noul#writing-a-noul-question), and [jaggedness](https://docs.typesafe.ai/model-jaggedness). Questions point to observable outputs or canonical state. Domain manifests exclude unrelated evidence. Code owns numeric/date validation, thresholding, result completeness and aggregation. Any failed assertion blocks completion and retains domain/test/assertion IDs. The 15+ requirement comes from the user. Both presets retain provisional pass threshold 0.8 (intermediate probabilities above 0.2 block completion as uncertain); offline doubles prove wiring only, not calibration or semantic accuracy. No paid/live inference is authorized.
